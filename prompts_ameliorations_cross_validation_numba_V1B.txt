### Reformulation des Prompts pour Aider

Conformément à votre demande, je reformule les cinq prompts précédemment proposés pour l'outil Aider. Chaque prompt est restructuré en une liste numérotée de tâches spécifiques, afin de faciliter les références ultérieures. Cette décomposition permet une application séquentielle et ciblée sur le script original ("cross-validation-numba_V1B.py"). Les tâches sont formulées de manière claire et précise, en respectant l'ordre logique des modifications. Vous pouvez référencer une tâche par son numéro (par exemple, "tâche 2.3") lors d'interactions futures.

#### Prompt 1 : Améliorations des Performances
Ce prompt se concentre sur l'optimisation des performances du script. Les tâches sont les suivantes :
1.1. Étendez l'utilisation de Numba en appliquant le décorateur @njit à la méthode create_entry_exit_conditions dans la classe ATDMFStrategy, en veillant à ce que les opérations internes soient compatibles avec Numba (par exemple, en convertissant les DataFrames en tableaux NumPy si nécessaire).
1.2. Ajoutez du caching en utilisant functools.lru_cache aux fonctions d'indicateurs telles que compute_bars_since_below et bollinger_horizontal_signal_nb, en configurant un maxsize approprié (par exemple, 128) pour limiter l'utilisation de la mémoire.
1.3. Dans la méthode optimize_parameters de la classe WFOOptimizer, remplacez la recherche exhaustive sur grille (grid search) par une optimisation bayésienne en intégrant la bibliothèque Optuna ; importez Optuna et configurez un sampler (par exemple, TPESampler) pour limiter le nombre d'essais à un maximum de 100, en adaptant la fonction objectif pour évaluer les paramètres.
1.4. Optimisez la gestion de la mémoire en supprimant les appels inutiles à .copy() sur les DataFrames (par exemple, dans walk_forward_optimization, utilisez des vues au lieu de copies pour in_sample_df et out_sample_df).
1.5. Dans la fonction run_backtest, favorisez l'utilisation directe de tableaux NumPy pour les opérations sur les données, en évitant les conversions répétées entre pandas et NumPy.

#### Prompt 2 : Améliorations de l'Ergonomie
Ce prompt vise à améliorer l'interface utilisateur et la robustesse du script. Les tâches sont les suivantes :
2.1. Dans la fonction main(), étendez l'analyseur argparse en ajoutant un argument --param_grid de type str (format JSON) pour permettre la spécification d'une grille de paramètres personnalisée, avec une valeur par défaut correspondant à get_param_grid().
2.2. Ajoutez un argument --output_dir de type str (valeur par défaut 'WFO_Results') pour permettre à l'utilisateur de choisir le répertoire de sortie des résultats et visualisations.
2.3. Ajoutez un argument --verbose de type bool pour activer le niveau de logging DEBUG si vrai, en modifiant logging.basicConfig en conséquence au début du script.
2.4. Ajoutez un argument --no_viz de type bool pour sauter l'appel à visualize_wfo_results si vrai, afin d'accélérer les exécutions sans visualisation.
2.5. Dans la fonction load_data, implémentez une validation des entrées en vérifiant la validité des dates (par exemple, en utilisant datetime pour comparer start_date et end_date) et l'existence du fichier (via os.path.exists), en levant des exceptions personnalisées avec des messages explicatifs.
2.6. À la fin de la fonction main(), affichez un résumé des performances out-of-sample (par exemple, la moyenne des returns et du ratio de Sharpe) directement à l'écran, en utilisant print pour une sortie structurée.
2.7. Améliorez le logging en ajoutant des timestamps plus précis (par exemple, en incluant les millisecondes dans le format) et en ajoutant des messages spécifiques pour le début et la fin de chaque fenêtre WFO dans walk_forward_optimization.

#### Prompt 3 : Améliorations de la Modularité (Séparation en Modules)
Ce prompt restructure le code pour une meilleure maintenabilité. Les tâches sont les suivantes :
3.1. Créez un fichier config.py contenant les classes WFOSettings et StrategyConfig, en les convertissant en dataclasses (via from dataclasses import dataclass) pour une validation et une initialisation simplifiées.
3.2. Créez un fichier indicators.py regroupant toutes les fonctions décorées @njit (par exemple, rolling_median, compute_bars_since_below) et les IndicatorFactory (par exemple, EcartBollingerBorne).
3.3. Créez un fichier strategies.py contenant la classe abstraite TradingStrategy et la classe concrète ATDMFStrategy.
3.4. Créez un fichier optimizer.py contenant la classe WFOOptimizer et la fonction run_backtest.
3.5. Créez un fichier utils.py regroupant les fonctions load_data, get_param_grid, get_metrics_info, et toute autre fonction utilitaire.
3.6. Créez un fichier viz.py contenant la fonction visualize_wfo_results.
3.7. Dans un fichier main.py, conservez la fonction main() et effectuez tous les imports nécessaires depuis les modules créés (par exemple, from config import WFOSettings).
3.8. Modifiez le constructeur de WFOOptimizer pour accepter une instance de TradingStrategy en paramètre, rendant la stratégie injectable (par exemple, self.strategy = strategy), et adaptez les appels internes (comme dans walk_forward_optimization) pour utiliser self.strategy au lieu d'instancier ATDMFStrategy directement.

#### Prompt 4 : Ajout d'Extensions Modulaires
Ce prompt ajoute des mécanismes pour étendre le script. Les tâches sont les suivantes :
4.1. Dans le fichier config.py, utilisez enum.Enum pour définir des énumérations, par exemple pour optimization_metric (valeurs comme SHARPE, RETURN) et matype (valeurs comme 0 pour SMA, 1 pour EMA), en les intégrant aux classes de configuration.
4.2. Dans le fichier optimizer.py, ajoutez une méthode add_custom_metric à la classe WFOOptimizer, prenant un dict en paramètre (par exemple, {'name': 'custom_metric', 'weight': 0.5, 'func': lambda portfolio: ...}) pour permettre l'ajout de métriques personnalisées.
4.3. Dans le fichier strategies.py, modifiez la méthode create_signal_generators pour accepter un dict de métriques personnalisées et les intégrer dans le calcul du combined_score lors de l'optimisation.
4.4. Assurez-vous que la grille de paramètres (param_grid) puisse être étendue dynamiquement via l'argument CLI --param_grid, en parsant le JSON dans main() et en le passant à WFOOptimizer.

#### Prompt 5 : Intégration Finale et Tests
Ce prompt assure l'intégration et la validation globale. Les tâches sont les suivantes :
5.1. Intégrez toutes les modifications des prompts précédents en vérifiant la cohérence entre les modules (par exemple, ajoutez des fichiers __init__.py dans les répertoires si nécessaire pour les imports).
5.2. Ajoutez des docstrings détaillées (au format Google ou NumPy) à toutes les classes et fonctions principales, en décrivant les paramètres, les retours et les exceptions potentielles.
5.3. Dans la fonction main(), enveloppez le code principal dans un bloc try/except global pour capturer les erreurs et les logger via logger.error, en évitant de propager les exceptions.
5.4. Ajoutez les imports manquants (par exemple, import optuna, from pydantic import BaseModel si utilisé pour les configs, from enum import Enum) en haut du fichier main.py ou des modules concernés.
5.5. Exécutez un test minimal dans le script (par exemple, avec n_windows=1 et un petit dataset) pour vérifier le fonctionnement, en mesurant le temps total d'exécution (via time.time()) et en loggant une comparaison avec la version originale pour confirmer les gains de performance.
